# Epics

These are the capabilities Winter Workspace intends to establish, in proposed product-priority order, not a status
board. Each epic owns its requirements and records its own delivery state.

| Epic                                                                                                                 | Capability                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`epic:parallel-workspaces/component-runtime`](./work/parallel-workspaces/component-runtime/epic.md)                 | Engineers and agents invoke Workspace independently, discover its commands, and receive unambiguous results without Python or Fleet.                               |
| [`epic:parallel-workspaces/workspace-configuration`](./work/parallel-workspaces/workspace-configuration/epic.md)     | Engineers declare one workspace and its local overrides without commands disagreeing about scope or effective settings.                                            |
| [`epic:parallel-workspaces/repository-catalog`](./work/parallel-workspaces/repository-catalog/epic.md)               | Engineers manage project and standalone repositories without hand-editing repeated configuration or losing repository-specific rules.                              |
| [`epic:parallel-workspaces/reproducible-inputs`](./work/parallel-workspaces/reproducible-inputs/epic.md)             | Engineers select and record shared repository revisions and compare workspace definitions without changing feature work.                                           |
| [`epic:parallel-workspaces/workspace-bootstrap`](./work/parallel-workspaces/workspace-bootstrap/epic.md)             | Engineers create a workspace that owns configuration and context rather than a fork of Winter's framework source.                                                  |
| [`epic:agent-ready-operation/context-navigation`](./work/agent-ready-operation/context-navigation/epic.md)           | Agents find version-matched framework, project, and extension guidance without loading everything or missing essential safety rules.                               |
| [`epic:parallel-workspaces/environment-lifecycle`](./work/parallel-workspaces/environment-lifecycle/epic.md)         | Engineers reconcile, inspect, reset, and retire feature worktrees without abandoning local work or disturbing another environment.                                 |
| [`epic:parallel-workspaces/coordinated-git`](./work/parallel-workspaces/coordinated-git/epic.md)                     | Engineers fetch, compare, connect, move, and publish work across repositories with explicit preflight refusals and partial-failure results.                        |
| [`epic:parallel-workspaces/safe-history`](./work/parallel-workspaces/safe-history/epic.md)                           | Engineers deliberately change checked-out history or remove untracked files without hidden scope expansion or abandoned local work.                                |
| [`epic:parallel-workspaces/stacked-history`](./work/parallel-workspaces/stacked-history/epic.md)                     | Engineers restack dependent feature branches in the right order and recover from conflicts without replaying the wrong commits.                                    |
| [`epic:running-environments/scope-environment`](./work/running-environments/scope-environment/epic.md)               | Engineers inspect and use deterministic scope-specific variables and ports without collisions or hidden mutation.                                                  |
| [`epic:running-environments/resource-provisioning`](./work/running-environments/resource-provisioning/epic.md)       | Engineers provision and clean resources for a declared scope without guessing what is ready or deleting another scope's data.                                      |
| [`epic:running-environments/service-orchestration`](./work/running-environments/service-orchestration/epic.md)       | Engineers start, stop, inspect, and follow services through one provider-independent Workspace interface.                                                          |
| [`epic:running-environments/provider-tmux`](./work/running-environments/provider-tmux/epic.md)                       | Engineers run isolated tmux-backed service environments with readiness, log capture, and workspace-qualified cleanup, without first-party Python helpers.          |
| [`epic:running-environments/provider-docker`](./work/running-environments/provider-docker/epic.md)                   | Engineers run isolated Docker Compose scopes, inspect container readiness, and retain data across ordinary service shutdown without a first-party Python provider. |
| [`epic:running-environments/provider-process-compose`](./work/running-environments/provider-process-compose/epic.md) | Engineers reconcile and recover per-scope process-compose services without restarting unchanged processes or depending on first-party Python helpers.              |
| [`epic:parallel-workspaces/nested-workspaces`](./work/parallel-workspaces/nested-workspaces/epic.md)                 | Engineers operate systems containing other workspaces without recursive loops, accidental scope expansion, or concealed child failures.                            |
| [`epic:agent-ready-operation/executable-extensions`](./work/agent-ready-operation/executable-extensions/epic.md)     | Engineers run external provider and hook implementations without rebuilding Workspace or loading foreign code into its process.                                    |
| [`epic:agent-ready-operation/extension-management`](./work/agent-ready-operation/extension-management/epic.md)       | Engineers install, bind, update, and inspect extensions with visible dependencies and safe failure behavior.                                                       |
| [`epic:agent-ready-operation/harness-projection`](./work/agent-ready-operation/harness-projection/epic.md)           | Engineers receive the same managed context, agents, and skills in supported harnesses without overwriting hand-authored files.                                     |
| [`epic:agent-ready-operation/agent-model-resolution`](./work/agent-ready-operation/agent-model-resolution/epic.md)   | Engineers inspect agent definitions and select harness-appropriate models with deterministic overrides and understandable errors.                                  |
| [`epic:agent-ready-operation/workspace-diagnostics`](./work/agent-ready-operation/workspace-diagnostics/epic.md)     | Engineers identify setup, environment, resource, and provider problems without a diagnostic silently changing the workspace.                                       |
| [`epic:agent-ready-operation/context-quality`](./work/agent-ready-operation/context-quality/epic.md)                 | Engineers find convention and reference problems in agent-facing content, with deliberate fixes rather than unexpected rewrites.                                   |
| [`epic:agent-ready-operation/dependency-graph`](./work/agent-ready-operation/dependency-graph/epic.md)               | Engineers and agents inspect declared extension-module dependencies without confusing missing evidence with a complete graph.                                      |
| [`epic:agent-ready-operation/workspace-dashboard`](./work/agent-ready-operation/workspace-dashboard/epic.md)         | Engineers inspect and act on repositories, environments, and services from a terminal view that preserves command safety.                                          |
| [`epic:agent-ready-operation/artifact-space`](./work/agent-ready-operation/artifact-space/epic.md)                   | Agents resolve declared artifact locations without creating files, accepting path-like bucket names, or changing the workspace.                                    |
| [`epic:rust-adoption/workspace-migration`](./work/rust-adoption/workspace-migration/epic.md)                         | Existing users preview and deliberately adopt the new workspace layout while preserving feature work and owned context.                                            |
| [`epic:rust-adoption/parity-validation`](./work/rust-adoption/parity-validation/epic.md)                             | Users can judge the replacement against observable legacy capabilities, refusal rules, and declared differences in disposable workspaces.                          |
| [`epic:rust-adoption/workspace-release`](./work/rust-adoption/workspace-release/epic.md)                             | Engineers install a complete prebuilt Workspace component and understand its upgrade cost without requiring unrelated products.                                    |
